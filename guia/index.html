Em resumo

O INEMA Eleições 2026 é um painel aberto para acompanhar a apuração do 2º turno para Presidente com os dados oficiais do TSE (Tribunal Superior Eleitoral). Serve para quem quer ver o resultado do Brasil e de cada estado num mapa, sem números inventados. Um coletor busca os arquivos públicos do TSE a cada 15 segundos, confere as contas e publica arquivos prontos; o site só lê esses arquivos. Para acompanhar, basta abrir eleicoes.inema.club; para rodar o seu, você só precisa de Python 3.

O que é

Coleta, contrato e painel: três partes separadas

A coleta lê o TSE e grava arquivos; o contrato define o formato desses arquivos; o painel só lê os arquivos e desenha a tela. A coleta não sabe nada de tela, e o painel nunca fala com o TSE.

🗳️ Coletor que confere

Baixa só o estado que mudou. Antes de publicar, confere: votos dos candidatos = válidos; válidos + brancos + nulos = total; seções nunca diminuem. Se algo não fecha, aquele estado não é publicado e fica o último valor válido.

🗳️ Painel em duas versões

Central, com mapa real do Brasil que se preenche estado por estado, e Clássica, com 4 estilos (noite, papel, telejornal e alto contraste). Clique num estado e abre o painel dele.

🗳️ Simulação para testar

Botão Simulação no menu: a apuração vai de 0% a 100% em cerca de um minuto, com nomes fictícios e com eleitorado, comparecimento, brancos e nulos de cada estado tirados do 1º turno.

Como funciona

Do arquivo do TSE até a sua tela

Quem visita o site só baixa arquivos prontos. O único que conversa com o TSE é o coletor, uma vez a cada 15 segundos. O manifesto (latest.json) é a lista do que está valendo agora; ele é sempre o último arquivo publicado, para nunca apontar para um arquivo que ainda não chegou.

Índice do TSE (só o que mudou)→ Guarda o arquivo original→ Confere as contas→ Publica versões novas→ Manifesto por último→ Site lê a cada 15 s

Só o que mudou

O coletor pede o índice com etiqueta de versão (ETag). Sem novidade, o TSE responde "não mudou" e nada é baixado.

Nada inventado

Percentuais vêm do próprio TSE. O que é conta do painel (diferença entre os dois, por exemplo) aparece marcado como calculado.

Rastreável

Cada número publicado traz a hora oficial do TSE, a hora da coleta, a versão e a impressão digital (sha256) do arquivo original.

Pré-requisitos

O que você precisa

Para só acompanhar a apuração: nada, é abrir o site. Para rodar o seu painel:

Python 3

Versão 3.8 ou mais nova. O coletor e o servidor de teste usam só a biblioteca padrão: não precisa instalar pacote. Os comandos são para Linux ou macOS (bash); no Windows, use o WSL.

python3 --version

Git

Para baixar o projeto.

git --version

Opcional: Cloudflare

Só se quiser publicar na internet. Precisa de Node.js e do wrangler logado na sua conta.

npx wrangler login
Guia de uso · passo a passo

Rodando o painel na sua máquina

Comandos reais do repositório, na ordem. Rode a partir da pasta do projeto.

1

Baixe o projeto

Clona o repositório público.

git clone https://github.com/inematds/eleicoes2026
cd eleicoes2026
2

Veja funcionando com a simulação

Sobe o servidor de teste em segundo plano (o & no fim) e abre o painel no modo simulação acelerada. Não precisa do TSE nem de dados. O servidor não mostra nada na tela; ele fica rodando até você parar.

python3 coleta/servidor_local.py --pasta site --porta 8470 &
# abra no navegador: http://localhost:8470/?sim=1
# não pare ainda: o passo 4 usa este servidor. Para parar no fim:
pkill -f "porta 8470"
3

Teste o coletor com o 1º turno real

Lê os dados finais do 1º turno (eleição 6257, 12 candidatos), confere tudo e publica em saida/teste1t/data. Rodando de novo, o TSE responde "não mudou".

python3 coleta/coletor.py --saida saida/teste1t --eleicao 6257 --turno 1 --pleito 3220 --n-cand 0 --uma-vez

No TSE, o pleito é a votação de um dia (3220 = 04/10/2026) e cada pleito tem as suas eleições (6257 = Presidente no 1º turno); --n-cand 0 desliga a conferência da quantidade de candidatos (no 1º turno são 12) e --uma-vez roda um ciclo só. Os passos 3, 4 e 5 precisam de internet: os dois primeiros acessam resultados.tse.jus.br e o 5 baixa de lá os dados do 1º turno que servem de base à simulação.

4

Ligue a coleta oficial do 2º turno

Fica vigiando o TSE a cada 15 segundos (eleição 6258, Presidente). Depois aponte o site para os dados oficiais.

python3 coleta/coletor.py --saida saida/oficial --intervalo 15 &
ln -sfn ../saida/oficial/data site/data   # o site passa a ler os dados oficiais
sleep 20; cat saida/oficial/status.json             # último ok, erros, bloqueios

O & no fim da primeira linha deixa o coletor rodando em segundo plano, junto com o servidor do passo 2; o sleep 20 espera o 1º ciclo antes de mostrar o status. Abra http://localhost:8470/ (sem ?sim=1): os dados aparecem depois do 1º ciclo, uns 15 segundos. Até a apuração começar (25/10, por volta das 17h), o painel mostra "Aguardando apuração" com tudo zerado: é o normal. Para parar o coletor: pkill -f "saida/oficial".

5

Teste as falhas com um "TSE falso"

Um servidor local imita o TSE com problemas de propósito: arquivo corrompido, seções diminuindo, índice e arquivos fora de ordem. O coletor tem de passar por tudo sem publicar nada errado.

mkdir -p saida/tsefalso
python3 coleta/servidor_local.py --pasta saida/tsefalso --porta 8471 &
python3 coleta/simular.py --saida saida/simlixo/data --intervalo 6 --uma-vez --modo-tse saida/tsefalso &
timeout 240 python3 coleta/coletor.py --saida saida/testemock --base http://127.0.0.1:8471/ --intervalo 3

O coletor para sozinho em 4 minutos (timeout 240), tempo para a simulação ir de 0% a 100%. Deu certo se saida/testemock/status.json mostrar pendentes e bloqueios vazios e grep BLOQUEIO saida/testemock/coleta.jsonl mostrar um bloqueio de SP (arquivo corrompido) e outro de RJ (seções diminuíram); BLOQUEIO é o nome do evento no log. O simulador termina sozinho; depois pare o servidor falso: pkill -f "porta 8471". Antes de começar, o simulador baixa uns 29 arquivos do TSE; com internet lenta, aumente o timeout.

6

Publique na internet (opcional)

Troque o domínio em ferramentas/cloudflare/wrangler.toml pelo seu e rode o publicador: ele envia ao Cloudflare a cada mudança dos dados.

python3 ferramentas/publicar_cf.py --laco 20

O wrangler é a ferramenta de linha de comando do Cloudflare; o publicador roda npx --yes wrangler@4 deploy, por isso o npx wrangler login dos pré-requisitos é obrigatório. Ele envia saida/oficial/data para a raiz do site e, se existir, a simulação em saida/simficticio/data para /simulacao/; então o coletor do passo 4 precisa estar rodando. Para publicar também a simulação, gere antes: python3 coleta/simular.py --saida saida/simficticio/data --intervalo 60 --ficticio &. O publicador fica rodando e vigiando; para parar, Ctrl+C. O domínio tem de estar numa zona da sua conta Cloudflare (zona = um domínio administrado nela).
