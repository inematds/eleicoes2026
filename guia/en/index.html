In short

INEMA Elections 2026 is an open dashboard for following the runoff count for President using official data from the TSE (Brazil's Superior Electoral Court). It is for anyone who wants to see the results for Brazil and for each state on a map, with no made-up numbers. A collector fetches the TSE's public files every 15 seconds, checks the math, and publishes ready-made files; the site only reads those files. To follow along, just open eleicoes.inema.club; to run your own, all you need is Python 3.

What it is

Collection, contract and dashboard: three separate parts

The collection reads the TSE and writes files; the contract defines the format of those files; the dashboard only reads the files and draws the screen. The collection knows nothing about the screen, and the dashboard never talks to the TSE.

🗳️ A collector that checks

It downloads only the state that changed. Before publishing, it checks: candidates' votes = valid votes; valid + blank + null = total; precincts never decrease. If something doesn't add up, that state is not published and the last valid value stays.

🗳️ Dashboard in two versions

Central, with a real map of Brazil that fills in state by state, and Classic, with 4 styles (night, paper, newscast and high contrast). Click a state to open its dashboard.

🗳️ Simulation for testing

Simulation button in the menu: the count goes from 0% to 100% in about a minute, with fictional names and with each state's electorate, turnout, blank and null votes taken from the 1st round.

How it works

From the TSE file to your screen

Site visitors only download ready-made files. The only one that talks to the TSE is the collector, once every 15 seconds. The manifest (latest.json) is the list of what is currently valid; it is always the last file published, so it never points to a file that has not arrived yet.

TSE index (only what changed)→ Stores the original file→ Checks the math→ Publishes new versions→ Manifest last→ Site reads every 15 s

Only what changed

The collector requests the index with a version tag (ETag). With nothing new, the TSE replies "not modified" and nothing is downloaded.

Nothing made up

Percentages come from the TSE itself. Anything computed by the dashboard (the difference between the two candidates, for example) is marked as calculated.

Traceable

Each published number carries the TSE's official time, the collection time, the version, and the fingerprint (sha256) of the original file.

Prerequisites

What you need

To just follow the count: nothing, just open the site. To run your own dashboard:

Python 3

Version 3.8 or newer. The collector and the test server use only the standard library: no packages to install. The commands are for Linux or macOS (bash); on Windows, use WSL.

python3 --version

Git

To download the project.

git --version

Optional: Cloudflare

Only if you want to publish on the internet. Requires Node.js and wrangler logged in to your account.

npx wrangler login
User guide · step by step

Running the dashboard on your machine

Real commands from the repository, in order. Run them from the project folder.

1

Download the project

Clones the public repository.

git clone https://github.com/inematds/eleicoes2026
cd eleicoes2026
2

See it working with the simulation

Starts the test server in the background (the & at the end) and opens the dashboard in accelerated simulation mode. It needs neither the TSE nor any data. The server shows nothing on screen; it keeps running until you stop it.

python3 coleta/servidor_local.py --pasta site --porta 8470 &
# open in the browser: http://localhost:8470/?sim=1
# don't stop it yet: step 4 uses this server. To stop it at the end:
pkill -f "porta 8470"
3

Test the collector with the real 1st round

Reads the final 1st-round data (election 6257, 12 candidates), checks everything, and publishes to saida/teste1t/data. When run again, the TSE replies "not modified".

python3 coleta/coletor.py --saida saida/teste1t --eleicao 6257 --turno 1 --pleito 3220 --n-cand 0 --uma-vez

At the TSE, the "pleito" is the voting held on one day (3220 = election day of Oct 4, 2026), and each pleito has its own races (6257 = the race for President in the 1st round); --n-cand 0 turns off the check on the number of candidates (in the 1st round there are 12) and --uma-vez runs a single cycle. Steps 3, 4 and 5 need internet access: the first two access resultados.tse.jus.br and step 5 downloads from there the 1st-round data that the simulation uses as its base.

4

Turn on the official runoff collection

It keeps watching the TSE every 15 seconds (election 6258, President). Then point the site to the official data.

python3 coleta/coletor.py --saida saida/oficial --intervalo 15 &
ln -sfn ../saida/oficial/data site/data   # the site now reads the official data
sleep 20; cat saida/oficial/status.json             # last ok, errors, blocks

The & at the end of the first line keeps the collector running in the background, alongside the server from step 2; the sleep 20 waits for the 1st cycle before showing the status. Open http://localhost:8470/ (without ?sim=1): the data appears after the 1st cycle, about 15 seconds. Until the count starts (Oct 25, around 5 pm), the dashboard shows "Aguardando apuração" (Awaiting count) with everything zeroed: this is normal. To stop the collector: pkill -f "saida/oficial".

5

Test failures with a "fake TSE"

A local server imitates the TSE with deliberate problems: corrupted file, precinct counts decreasing, index and files out of order. The collector has to get through all of it without publishing anything wrong.

mkdir -p saida/tsefalso
python3 coleta/servidor_local.py --pasta saida/tsefalso --porta 8471 &
python3 coleta/simular.py --saida saida/simlixo/data --intervalo 6 --uma-vez --modo-tse saida/tsefalso &
timeout 240 python3 coleta/coletor.py --saida saida/testemock --base http://127.0.0.1:8471/ --intervalo 3

The collector stops by itself after 4 minutes (timeout 240), which is the time the simulation needs to go from 0% to 100%. It worked if saida/testemock/status.json shows empty pending items and blocks, and grep BLOQUEIO saida/testemock/coleta.jsonl shows one block for SP (corrupted file) and another for RJ (precincts decreased); BLOQUEIO is the name of the event in the log. The simulator finishes by itself; then stop the fake server: pkill -f "porta 8471". Before starting, the simulator downloads about 29 files from the TSE; on a slow connection, increase the timeout.

6

Publish on the internet (optional)

Replace the domain in ferramentas/cloudflare/wrangler.toml with yours and run the publisher: it sends to Cloudflare every time the data changes.

python3 ferramentas/publicar_cf.py --laco 20

wrangler is Cloudflare's command-line tool; the publisher runs npx --yes wrangler@4 deploy, which is why the npx wrangler login from the prerequisites is mandatory. It sends saida/oficial/data to the site root and, if it exists, the simulation at saida/simficticio/data to /simulacao/; so the collector from step 4 must be running. To publish the simulation too, generate it first: python3 coleta/simular.py --saida saida/simficticio/data --intervalo 60 --ficticio &. The publisher keeps running and watching; to stop it, press Ctrl+C. The domain must be in a zone of your Cloudflare account (a zone = a domain managed there).
